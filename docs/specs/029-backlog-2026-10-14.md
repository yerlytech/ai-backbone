# 029 — The backlog of 2026-10-14, as one batch

Approved by the owner's word on 2026-10-14, carried by a sibling session:
work through the backbone's waiting backlog, in order of value, and release
when a change is done.

## What

The six open lines of `docs/backlog.md` on 2026-10-14 are built in one
attended session on the maintainer's machine and carried through the gate as
one version (3.38.0, a minor: doctor and session-start say new things). In
order of value:

1. n-276b7e, a Rust project hears about a published vulnerability in any
   crate its Cargo.lock locks. `.ai-backbone/upstream.py --advisories` reads
   every Cargo.lock in the project against the RustSec advisory database,
   fetched anonymously as one archive (no git: a person's git may reach
   GitHub with their own key) into a cache shared by every project on the
   machine and refreshed at most once a day. In upstream.py, not a file of
   its own: a new core file would pass the ceiling of files a new project
   has, which only the maintainer raises. Each finding names the crate, its
   version, the advisory, its title and the fixed version. `just doctor`
   prints the whole answer; `just session-start` prints only what it finds.
   It lives in the core, not in the Rust layer: a layer is the project's own
   file once copied, and no update would reach the Rust projects that exist.
2. The same line's second half: `just doctor` says when a row of
   `docs/upstream.toml` reads from `github:` something Cargo.lock locks as a
   crate, and names the `crates:` source to write instead.
3. n-f7e10e and its correction n-cdec6e, the trim's order. The measurement
   the correction asked for was made first, on one toolchain throughout, and
   it holds: removing by write time removes the dependencies in use, and
   every crate above one is compiled again. `buildtrim.py` now reads cargo's
   own records of what each piece was built against: what only a replaced
   root reaches goes first, the rest by when a build last used it, and what
   the current roots of the last day reach is never removed.
4. n-be0ac4, `just save` does not wait for another project's build when the
   lint hook would not run on what is saved (docs, Markdown).
5. n-ffb8cc, the Rust layer's `clean-own` cleans the release profile too.
6. n-3c54ee, the spec skill says what a night does when its spec ends before
   five hours and the maintainer approved a series, and when the next one's
   dependency is unmet.

## Why

A workspace locks 800 to 900 crates and nothing read them against published
vulnerabilities; a watch list follows a handful. A `github:` row missed four
patch releases of a crate that reached crates.io with no GitHub tag. The trim
removed the pieces a project still builds against, because a dependency is
compiled once and never written again. A docs-only save waited fifteen
minutes behind another project's tests. A release build in a worktree linked
old code after `clean-own`.

What the trim measurement found, on cargo 1.99.0 with no compiler cache: a
236 MB folder, 47 MB of it left behind by a feature change, trimmed with a cap
just under its size. By write time: 64 MB in 42 pieces removed, and the next
build compiled 43 crates again (8.1 s of a 9.3 s build from nothing). The new
order: the 11 pieces left behind removed, and the next build compiled nothing;
the same with the replaced root inside the last day. Read without removing
anything, a real 18.4 GB folder of 2409 pieces: the first quarter by write
time held 1566 pieces in use. A real 152 GB folder built in one day: 136 GB of
it is what the current roots reach, 7.5 GB may go; its cap of 60 is below what
its builds need, and the trim now says so instead of removing pieces in use
every hour. A file's read time was tried first and fails on macOS, which
writes one only at the first read after a write. A graph per profile was
tried and fails for a build for another target, which reaches the macros and
build scripts compiled for this machine in debug/.

## Not doing

- An advisory check in `lint`: a vulnerability published today would block
  every save of unrelated work, and lint must not need the network.
- cargo-audit or cargo-deny: each is an install the person would be asked
  for, on every machine. The database is a public git repository and its
  format is documented; the matching is the semver rule cargo uses.
- Yanked crates and `unmaintained` or `unsound` notices as warnings: the
  notices are counted on one line, yanked needs the registry index.
- `clean-own` for a custom profile or another target (`--profile`,
  `--target`): the line asked for release, and a layer is the project's own
  file to extend.
- doctor comparing sccache's size with the sum of the caps (n-f7e10e's second
  half): with the pieces in use kept, a trim no longer leans on the cache to
  bring dependencies back, and one project cannot know the others' caps.
